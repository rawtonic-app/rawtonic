# ADR 0005 — XML dependency remediation and advisory evidence
Status: accepted, 2026-10-01.

The inherited lockfile was necessary to retain compatible jxl-encoder SIMD dependencies (magetypes 0.9.26 / archmage 0.9.28). A broad update initially broke compilation, so dependency changes are targeted and verified.

A full RustSec scan found rustls RUSTSEC-2026-0285 and quick-xml RUSTSEC-2026-0194/0195, plus unmaintained dependencies. Upgrade rustls to 0.23.45 and yanked chacha20 0.10.1 to 0.10.2. The application already uses quick-xml 0.41; little_exif 0.6.23 pins 0.37.5. Vendor that small MIT/Apache crate, retain its source/licenses, and change only its quick-xml dependency to 0.41.0. This removes the vulnerable XML version without rewriting the EXIF codec. Record the local patch in THIRD_PARTY_NOTICES; return to upstream when a compatible release incorporates the update.

The remaining full advisory gate fails for unmaintained transitive packages: paste (2024-0436), proc-macro-error (2024-0370), ttf-parser (2026-0192), unic-char-property (2025-0081), unic-char-range (2025-0075), unic-common (2025-0080), unic-ucd-ident (2025-0100), unic-ucd-version (2025-0098). They arrive through image codecs, GTK/Tauri and text dependencies. Do not ignore them or call the full audit green. Migrate/fork their upstream consumers, then re-run platform builds and the full audit before production release. License/bans/source checks are separate and pass.

## Gate policy — 2026-10-16 (user decision)

- Merges: `scripts/check.sh` and CI (`ci.yml`) run `cargo deny check -W unmaintained advisories`. Vulnerabilities and unsound crates fail the gate; an unmaintained transitive crate is a warning, because it often needs an upstream release first and should not block unrelated work.
- Watch: `.github/workflows/advisories.yml` runs the full `cargo deny check advisories` after every merge into main and weekly, so a new advisory shows as a failed run.
- Releases: the full check must pass. `npm run package:mac` runs it before building, and the Linux AppImage workflow's build needs its `advisories` job. Ignore entries in `deny.toml` stay a user decision, each with a reason and an exit condition.

## Update — 2026-11-17

RustSec marked chrono unmaintained (RUSTSEC-2026-0543, recommended replacements jiff or time); `advisories.yml` failed on main from that day. No external crate needed it in a build: our own crates (catalog, cli, export, ingest, naming, the app) and the vendored rawler used it directly, and `trash` (system Trash on Linux) through its default `chrono` feature. Dates now use jiff 1.0 (BurntSushi, Unlicense OR MIT): strftime/strptime close to chrono's, real time zones; `time` was not needed. `trash` 5.2.6 → 5.4.0, whose upstream release made the same switch and keeps writing `DeletionDate` in the same local `%Y-%m-%dT%H:%M:%S` form (5.3.0's fixes come with it: encoded path decoding, path whitespace, Windows per-item errors; the new Portal backend stays off). chrono stays in `Cargo.lock` only as an optional dependency of `serde_with` (through tauri-utils) that no build enables — Cargo records optional dependencies named by weak features — so `cargo tree --workspace --all-features --target all -i chrono` prints nothing and `cargo deny check advisories` passes without ignore entries.

Behaviour is unchanged, pinned by tests committed before the swap and passing with chrono, then with jiff unchanged except their own construction helpers: naming tokens and every `{date:}`/`{time:}` format for years 0999–9999 incl. both ends of the two-digit-year window and every weekday, the naming JSON form; EXIF date spellings in ingest, export and the capture-time correction (incl. single-digit fields, leap days, out-of-range and placeholder dates, the whole 0001–9999 range to the nanosecond); search days and calendar periods; the stored RFC 3339 spellings of snapshots, catalog records, copy receipts and import reports; the backup date; local wall time to instant across both daylight-saving changes (Europe/Zurich, `crates/export/tests/local_capture_time.rs`); and rawler's modification time with offsets (`third_party/rawler/tests/rawtonic_last_modified.rs`). A differential run over 637 parse and 4,032 format cases found jiff equal to chrono except negative years (chrono `-0001`, jiff `-001`; unreachable, EXIF years start at 0001), a leap second `:60` (jiff reads `:59`) and fractions beyond nine digits (jiff refuses them; the export parser now cuts them to nine, as chrono did). A snapshot's stored time is checked with jiff's RFC 3339/ISO 8601 reader, which accepts every spelling chrono accepted except fractions beyond nine digits (Rawtonic always wrote milliseconds) and also some chrono refused (`+0200`, minutes without seconds, a bracketed zone). chrono 0.4's own readings at daylight-saving changes are kept on purpose rather than jiff's: a wall time the clocks passed twice takes the offset after the change (the later instant), the first second of a skipped hour the offset before it, and a later skipped second is read as UTC (export) or as no time (rawler). chrono's two backends differed there, and each platform keeps its own (`LocalRules` in `rawtonic_export::exif_processing`, `local_earliest_in` in rawler): on Unix chrono looked the time up on whole seconds and took the offset after the change for a repeated hour (its end included); on Windows it worked at full precision and took the offset before the change (both ends included), a skipped hour's exact start taking the offset before it and its exact end the offset after it. Both rule sets are tested on every platform with an explicit Europe/Zurich zone; the Unix values were measured with chrono, the Windows values follow chrono's `lookup_with_dst_transitions`. Not reproduced: chrono on Windows took the year's rules from Win32 (`GetTimeZoneInformationForYear`), jiff from its IANA database, so a historical year whose Windows and IANA rules differ can still read differently there. jiff's civil arithmetic with a duration goes through nanoseconds (about 292 years), so the capture-time correction moves wall times by whole days plus the time of day.
