# ADR 0014 — Library search and smart albums: one rule model in the catalog
Status: accepted (2026-10-20). Side-by-side use test against Lightroom Classic and Capture One open (G36, G37).

**Context.** The Library filtered in the webview over the loaded folder or album: file name and keyword text, rating, colour label and flag. Camera, lens, exposure and capture date were not indexed (the catalog had unused `camera`/`lens`/`capture_time` columns), so they could not be searched without reading every file's EXIF, and there were no smart albums (an unused `smart_collections` table). Lightroom Classic has a Library Filter bar (text over chosen fields, attributes, and metadata columns listing each value with its count, where choosing values narrows the next column) and, separately, smart collections: rules over about forty fields, matched all, any or none, with nested rule groups. Capture One has a Filters tool (value lists with counts, Advanced Search with rules) and smart albums whose rules are the same search criteria; a smart album inside a project or group searches within it. (Both from the editors' documentation and earlier notes; not yet observed side by side here.)

**Decision.** One rule model for the Library filter and smart albums (`rawtonic_catalog::query`): a rule is a condition on one field or a group of rules that must all, any or none hold, nested freely (depth ≤ 16, ≤ 500 conditions). Fields: any searchable text (path, keywords, title, caption, creator, IPTC fields, camera, lens), file name, keyword, camera model, camera maker, lens, file type (RAW, DNG, JPEG, HEIF, TIFF, PNG, other), rating, flag, colour label, ISO, focal length, aperture, shutter speed, capture date and import date (on, before, after, between, in or not in the last n days/weeks/months/years), album, group or smart album, folder (with or without subfolders), missing photographs, Previous Import. Each rule is compiled to one SQL query over the catalog; no file is read, so a smart album is evaluated whenever it is shown or counted and always shows what the library holds now. Text matches part of a word (`0123` finds `DSC00123.ARW`), through a trigram index for words of three or more characters (or a row scan for words most photographs hold, which is faster than collecting them from the index), ignoring case: the index holds text folded by the library's own function (`rawtonic_fold`, Unicode lower case) and compares exactly, and every scan folds with the same function, so which way a word is found never changes the result. Conditions on a value a photograph lacks (no ISO, no capture date) are false, so a "none" group keeps such photographs. Folders inside the library are stored relative to it, so smart albums move with a closed session.

The Library filter is this model: the search box is a text rule, the metadata lists (capture month, camera, lens, keyword, file type, ISO, focal length, aperture) list each value of the shown folder or album with its count within the search box and the culling filters; any chosen value of a list, every list. A list's counts leave out its own choice, so another value of it shows what it adds (Capture One's Filters tool; Lightroom's columns count within the columns to their left instead). The rating, label and flag filters keep evaluating in the grid as before, since they must follow a key press before its write reaches the catalog; they mean the same as the rating, label and flag rules (`cullingRules`), and "Save as smart album" turns everything the Library filters by (the shown folder or album too) into one smart album's rules, which neither editor's filter bar does in one step. Smart albums live among the albums (kind `smart`, schema 11): groups hold them, they are moved, renamed and deleted as albums are, rules can name albums, groups and other smart albums (a loop matches nothing there), and photographs cannot be dropped on them. Albums and the open smart album refresh after each catalog write (rating, label, flag, keyword, text fields), as Lightroom's smart collections do.

Capture facts (camera, lens, exposure, capture time from EXIF; never a file date as capture time) are recorded with each verified ingest in the photograph's transaction, and a background pass reads the header (at most the first 16 MiB) of every other photograph once, announcing what it recorded so searches and smart albums refresh (`facts_read`; `rawtonic facts` in the CLI). Keywords are kept one row each by triggers on the metadata JSON (`asset_keywords`), whatever writes it.

**Not taken / open.** Lightroom fields not in the model yet: edit date, "has adjustments", GPS and location, copyright status, collection by name, treatment, crop/aspect, video. Importing Lightroom smart collection rules: their criteria are stored as a serialized Lua table per collection; a reader plus a translation of each criterion is not trivial and no real Lightroom catalog with smart collections is available here to test it, so it is recorded in G36 rather than built. Capture One smart album import likewise.

**Consequences.** A library opened by this version is migrated to schema 11 (keywords filled from the metadata already stored, the search index rebuilt with camera and lens, albums kept with their photographs), which older Rawtonic versions refuse to open. Capture facts of photographs added before are read in the background after opening; until then they are not found by camera, lens or exposure rules. Measured on a synthetic 50,000-photograph session (`rawtonic search-bench`, Linux PC, numbers in G37).
