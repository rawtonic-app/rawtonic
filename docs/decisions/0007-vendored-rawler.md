# ADR 0007 — Vendored rawler with Rawtonic patches
Status: accepted, 2026-10-05.

rawler (LGPL-2.1, RapidRAW's fork of dnglab) is the RAW decoder under the inherited engine. It was a git dependency pinned to commit 934af4b; its camera list is compiled in and cannot be extended at runtime, and decoder defects found on the raw.pixls.us corpus could only be worked around in `src-tauri` (the Olympus high-resolution colour pattern) or not at all (Samsung Expert RAW DNGs decoding to garbage, the Sony ILME-FX2 refused as an unknown camera). The user's decision of 2026-10-05: patch or vendor rawler, or build an improved variant, when that benefits Rawtonic; RAW quality has to match or beat Lightroom and Capture One.

Decision: the crate is vendored into `third_party/rawler` (upstream `rawler/` directory without its 44 MB sample test data, benches and fuzz targets) and selected through a `[patch]` entry for the original git source in the workspace `Cargo.toml`, so `Cargo.lock` and every dependent keep the same package name and version. It is a workspace member: `cargo fmt --all --check`, `cargo clippy --workspace -- -D warnings` and `cargo test --workspace` cover it. Upstream's rustfmt settings are kept in `third_party/rawler/rustfmt.toml`, and `[lints]` in its manifest allow upstream's clippy and unused-code warnings, so the gates act on Rawtonic's patches without reformatting or restyling 40,000 lines of upstream code (which would make later merges from upstream impractical).

Rules: every change is marked `Rawtonic patch` in the source and listed in `third_party/rawler/RAWTONIC_PATCHES.md` with the defect it fixes and its test. The LGPL-2.1 license text and the AUTHORS file stay with the crate; `THIRD_PARTY_NOTICES.md` records the vendoring. Fixes are preferred in the decoder over workarounds in `src-tauri` (the `use_mode_color_pattern` ORF workaround was removed when the decoder was fixed). Changes that are not Rawtonic-specific are candidates to send upstream. Returning to a released upstream version requires that every listed patch is merged or re-applied; the patch list is the checklist.

Not covered: the Sony ILCE-7M5 "compressed" files (compression type 32766) use a new, undocumented container (a 64-byte header with version, width and height followed by entropy-coded data, maker tags 0x7032/0x7035/0x7037) that no open-source decoder reads yet; they stay refused with a clear error.
